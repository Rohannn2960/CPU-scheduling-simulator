Laboratory Procedure & Experiment Manual

1. AIM of the Experiment

To simulate, analyze, and evaluate the performance of various Uniprocessor CPU Scheduling Algorithms (First-Come First-Served, Shortest Job First - Non-Preemptive, Shortest Remaining Time First, Priority Scheduling, Round Robin, and Multilevel Feedback Queue) in terms of Turnaround Time (TAT), Waiting Time (WT), Response Time (RT), and CPU Utilization.

2. Theoretical Foundations

CPU scheduling is the basis of multiprogrammed operating systems. By switching the CPU among processes, the operating system can make the computer more productive. Whenever the CPU becomes idle, the OS must select one of the processes in the Ready Queue to be executed. The selection is carried out by the Short-Term Scheduler (or CPU Scheduler).

Core Scheduling Metrics & Mathematical Formulas:
1. Completion Time (CT) = Instant at which the process finishes its total execution.
2. Turnaround Time (TAT) = Completion Time - Arrival Time   →   TAT = CT - AT
3. Waiting Time (WT) = Turnaround Time - Burst Time   →   WT = TAT - BT
4. Response Time (RT) = Time of First CPU Allocation - Arrival Time   →   RT = FirstRun - AT
5. Average Turnaround Time = (Σ TAT) / Total Processes
6. Average Waiting Time = (Σ WT) / Total Processes
7. CPU Utilization = (Total Busy Execution Time / Total Schedule Length) × 100%
8. Throughput = Number of processes completed / Total Time Units

3. Classification of Scheduling Algorithms

Algorithm Preemptive? Scheduling Criterion Advantages Disadvantages / Pitfalls
FCFS No Arrival Time (AT) Simplest to implement; No starvation. Convoy Effect: Short processes stuck behind long process; Poor average WT.
SJF (Non-Preemptive) No Burst Time (BT) Mathematically optimal for minimizing average waiting time for given set of processes. Burst time is difficult to predict in advance; Risk of starvation for long processes.
SRTF (SJF Preemptive) Yes Remaining Burst Time Better response time than SJF Non-Preemptive; very low average waiting time. Frequent context switching overhead; Severe starvation possible for CPU-heavy tasks.
Priority Scheduling Both (P / NP) Priority Value Ensures critical/real-time jobs run first. Starvation (Indefinite Blocking). Solved via Aging.
Round Robin (RR) Yes Time Quantum ($q$) + FIFO Fair CPU share; Best for interactive/time-sharing systems; Guaranteed response time bound. Performance hinges critically on $q$: If $q$ is too small → high context switch overhead; If $q$ is too large → degrades to FCFS.
MLFQ Yes Dynamic Multi-Queue Priority Adapts automatically to I/O-bound vs CPU-bound jobs without prior knowledge of burst times. Complex configuration (quantum per queue, promotion/demotion policy, aging).

4. Step-by-Step Lab Procedure

Step 1: Tabulate the list of processes with their given Arrival Times ($AT$), Burst Times ($BT$), and Priority values.
Step 2: Sort or place processes into the Ready Queue in accordance with the rules of the selected algorithm.
Step 3: Step through time starting from $t = 0$. If no process has arrived, mark the CPU as IDLE.
Step 4: Once a process gains the CPU, draw its time slice on the Gantt chart. In preemptive algorithms (SRTF, Priority Preemptive, RR), continuously check for higher priority arrivals or quantum expiration.
Step 5: Record the Completion Time ($CT$) of each process upon termination.
Step 6: Calculate $TAT = CT - AT$ and $WT = TAT - BT$ for every process.
Step 7: Compute the overall system averages ($Avg\ TAT$, $Avg\ WT$) and document in the observation table.

Formal Pseudo-Code for Schedulers

1. First-Come, First-Served (FCFS)

Algorithm FCFS_Scheduling(Processes[1..N]):
  Sort Processes in ascending order of Arrival Time (AT)
  currentTime = 0
  
  For each Process P in Processes:
    If currentTime < P.AT:
      currentTime = P.AT              // CPU remains idle until process arrives
    
    P.StartTime = currentTime
    P.CompletionTime = currentTime + P.BurstTime
    P.TurnaroundTime = P.CompletionTime - P.ArrivalTime
    P.WaitingTime = P.TurnaroundTime - P.BurstTime
    P.ResponseTime = P.StartTime - P.ArrivalTime
    
    currentTime = P.CompletionTime
  
  Calculate Avg_TAT = Sum(P.TurnaroundTime) / N
  Calculate Avg_WT = Sum(P.WaitingTime) / N

2. Shortest Remaining Time First (SRTF - Preemptive SJF)

Algorithm SRTF_Scheduling(Processes[1..N]):
  Initialize remaining_bt[i] = P[i].BurstTime for all i
  completed = 0, currentTime = 0, min_index = -1
  
  While completed < N:
    // Find process with shortest remaining burst time among arrived processes
    min_rem = INFINITY
    min_index = -1
    
    For i = 1 to N:
      If P[i].AT <= currentTime AND remaining_bt[i] > 0:
        If remaining_bt[i] < min_rem:
          min_rem = remaining_bt[i]
          min_index = i
    
    If min_index == -1:
      currentTime = currentTime + 1    // CPU Idle
      Continue
    
    // Mark first response time if this is first execution
    If remaining_bt[min_index] == P[min_index].BurstTime:
      P[min_index].ResponseTime = currentTime - P[min_index].AT
      
    // Execute 1 unit of time
    remaining_bt[min_index] = remaining_bt[min_index] - 1
    currentTime = currentTime + 1
    
    If remaining_bt[min_index] == 0:
      completed = completed + 1
      P[min_index].CompletionTime = currentTime
      P[min_index].TAT = P[min_index].CompletionTime - P[min_index].AT
      P[min_index].WT = P[min_index].TAT - P[min_index].BT

3. Round Robin (RR) with Time Quantum $q$

Algorithm RoundRobin_Scheduling(Processes[1..N], Quantum q):
  Sort Processes by Arrival Time
  Queue readyQueue
  currentTime = 0, completed = 0
  Mark all processes as not in queue
  
  Enqueue first arrived process into readyQueue
  
  While completed < N:
    If readyQueue is empty:
      Advance currentTime to next arriving process
      Enqueue newly arrived process
      Continue
      
    P = readyQueue.dequeue()
    
    If P is running for first time:
      P.ResponseTime = currentTime - P.AT
      
    execTime = min(q, P.remaining_bt)
    P.remaining_bt = P.remaining_bt - execTime
    currentTime = currentTime + execTime
    
    // Check and enqueue all newly arrived processes during [currentTime - execTime, currentTime]
    For each process Pi not yet arrived:
      If Pi.AT <= currentTime:
        readyQueue.enqueue(Pi)
        
    If P.remaining_bt > 0:
      readyQueue.enqueue(P)           // Re-insert preempted process at tail
    Else:
      completed = completed + 1
      P.CompletionTime = currentTime
      P.TAT = P.CompletionTime - P.AT
      P.WT = P.TAT - P.BT

#include <stdio.h>

struct Process {
    int pid;
    int at;  // Arrival Time
    int bt;  // Burst Time
    int ct;  // Completion Time
    int tat; // Turnaround Time
    int wt;  // Waiting Time
    int rt;  // Response Time
};

void sort_by_arrival(struct Process p[], int n) {
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - i - 1; j++) {
            if (p[j].at > p[j + 1].at) {
                struct Process temp = p[j];
                p[j] = p[j + 1];
                p[j + 1] = temp;
            }
        }
    }
}

int main() {
    int n;
    printf("Enter number of processes: ");
    if (scanf("%d", &n) != 1) return 1;

    struct Process p[n];
    for (int i = 0; i < n; i++) {
        p[i].pid = i + 1;
        printf("P%d: Enter Arrival Time and Burst Time: ", i + 1);
        scanf("%d %d", &p[i].at, &p[i].bt);
    }

    sort_by_arrival(p, n);

    int current_time = 0;
    float total_tat = 0, total_wt = 0;

    printf("\n--- GANTT CHART ---\n|");
    for (int i = 0; i < n; i++) {
        if (current_time < p[i].at) {
            printf(" IDLE (%d-%d) |", current_time, p[i].at);
            current_time = p[i].at;
        }
        p[i].rt = current_time - p[i].at;
        current_time += p[i].bt;
        p[i].ct = current_time;
        p[i].tat = p[i].ct - p[i].at;
        p[i].wt = p[i].tat - p[i].bt;

        total_tat += p[i].tat;
        total_wt += p[i].wt;
        printf(" P%d (%d-%d) |", p[i].pid, current_time - p[i].bt, current_time);
    }

    printf("\n\nPID\tAT\tBT\tCT\tTAT\tWT\tRT\n");
    for (int i = 0; i < n; i++) {
        printf("P%d\t%d\t%d\t%d\t%d\t%d\t%d\n",
               p[i].pid, p[i].at, p[i].bt, p[i].ct, p[i].tat, p[i].wt, p[i].rt);
    }

    printf("\nAverage Turnaround Time = %.2f", total_tat / n);
    printf("\nAverage Waiting Time    = %.2f\n", total_wt / n);
    return 0;
}

#include <stdio.h>
#include <stdbool.h>

struct Process {
    int pid, at, bt, rem_bt, ct, tat, wt, rt;
    bool in_queue, started;
};

int main() {
    int n, tq;
    printf("Enter number of processes: ");
    scanf("%d", &n);
    printf("Enter Time Quantum: ");
    scanf("%d", &tq);

    struct Process p[n];
    for (int i = 0; i < n; i++) {
        p[i].pid = i + 1;
        printf("P%d (AT, BT): ", i + 1);
        scanf("%d %d", &p[i].at, &p[i].bt);
        p[i].rem_bt = p[i].bt;
        p[i].in_queue = false;
        p[i].started = false;
    }

    int queue[1000], front = 0, rear = 0;
    int current_time = 0, completed = 0;
    float total_tat = 0, total_wt = 0;

    // Push initial processes that arrive at 0
    for (int i = 0; i < n; i++) {
        if (p[i].at <= current_time) {
            queue[rear++] = i;
            p[i].in_queue = true;
        }
    }

    while (completed < n) {
        if (front == rear) { // Queue is empty
            current_time++;
            for (int i = 0; i < n; i++) {
                if (p[i].at <= current_time && !p[i].in_queue && p[i].rem_bt > 0) {
                    queue[rear++] = i;
                    p[i].in_queue = true;
                }
            }
            continue;
        }

        int idx = queue[front++];
        if (!p[idx].started) {
            p[idx].rt = current_time - p[idx].at;
            p[idx].started = true;
        }

        int exec_time = (p[idx].rem_bt > tq) ? tq : p[idx].rem_bt;
        p[idx].rem_bt -= exec_time;
        current_time += exec_time;

        // Enqueue new arrivals during this execution window
        for (int i = 0; i < n; i++) {
            if (p[i].at <= current_time && !p[i].in_queue && p[i].rem_bt > 0) {
                queue[rear++] = i;
                p[i].in_queue = true;
            }
        }

        if (p[idx].rem_bt > 0) {
            queue[rear++] = idx; // Re-enqueue
        } else {
            p[idx].ct = current_time;
            p[idx].tat = p[idx].ct - p[idx].at;
            p[idx].wt = p[idx].tat - p[idx].bt;
            total_tat += p[idx].tat;
            total_wt += p[idx].wt;
            completed++;
        }
    }

    printf("\nPID\tAT\tBT\tCT\tTAT\tWT\tRT\n");
    for (int i = 0; i < n; i++) {
        printf("P%d\t%d\t%d\t%d\t%d\t%d\t%d\n",
               p[i].pid, p[i].at, p[i].bt, p[i].ct, p[i].tat, p[i].wt, p[i].rt);
    }
    printf("\nAvg TAT: %.2f | Avg WT: %.2f\n", total_tat / n, total_wt / n);
    return 0;
}

Viva Voce & Frequently Asked Interview Questions

Comprehensive answers to frequent university practical examination and technical interview questions.

Q1. What is the Convoy Effect, and which algorithm does it afflict?
The Convoy Effect occurs in non-preemptive algorithms like FCFS when a CPU-bound process with a huge burst time acquires the CPU before several short I/O-bound processes. The short processes pile up in the ready queue waiting for the heavy process to yield, causing overall CPU and I/O device utilization to plummet and skyrocketing average waiting time.
Q2. Why is pure Shortest Job First (SJF) impossible to implement in practice?
SJF requires exact prior knowledge of the next CPU burst length for every incoming process. In real-world multi-tasking operating systems, user inputs, disk delays, and dynamic branches make future execution duration nondeterministic. Real systems approximate SJF by predicting CPU burst length using Exponential Smoothing: $\tau_{n+1} = \alpha t_n + (1 - \alpha)\tau_n$.
Q3. What is Starvation (Indefinite Blocking) and how does Aging solve it?
Starvation occurs in Priority and SJF schedulers when low-priority or long processes wait indefinitely in the Ready Queue because a continuous stream of higher-priority or shorter jobs arrives. Aging is a mitigation technique where the OS gradually increments the priority of processes that wait in the system for extended periods. Eventually, even the lowest-priority process ascends to highest priority and executes.
Q4. What is the trade-off in selecting the Round Robin Time Quantum ($q$)?
If $q$ is extremely large ($q \to \infty$), Round Robin degrades into FCFS, ruining interactive responsiveness. If $q$ is extremely small ($q \to 0$), the CPU spends a dominant percentage of cycles performing Context Switching (saving registers, flushing CPU caches, reloading PCB), dragging throughput down to zero. A standard rule of thumb is that 80% of CPU bursts should be shorter than the time quantum (typically 10ms to 100ms in production OSs).
Q5. What is the difference between Turnaround Time and Response Time?
Turnaround Time (TAT) is the entire duration from process submission to process termination ($CT - AT$). It reflects how long the user waited for completion. Response Time (RT) is the time from submission until the process produces its first output or receives its first CPU time slice ($FirstExec - AT$). In interactive GUI systems, Response Time is far more important for user experience than Turnaround Time.
Q6. How does Multilevel Feedback Queue (MLFQ) differ from standard Multilevel Queue?
In a static Multilevel Queue, processes are permanently assigned to one queue based on their type (e.g. system, interactive, batch) and cannot change queues. In MLFQ, processes are allowed to move between queues based on their observed runtime behavior. If a process uses up its full time slice (CPU-intensive), it is demoted to a lower-priority queue with a larger quantum. If an I/O process yields early, it stays in or is promoted to a high-priority responsive queue.
